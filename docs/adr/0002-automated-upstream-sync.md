# Automated Upstream Sync

The fork's code follows upstream `master`, while its releases follow upstream's release cadence. `.github/workflows/sync-upstream.yml` runs daily: it merges new upstream `master` commits into `master` (fork changes are preserved by merging, never by rewriting), aligns `.fvmrc` with upstream's CI Flutter version, runs `flutter test`, and pushes. When upstream's latest release tag is contained in `master` and the fork has no release titled "跟随上游 <tag>" yet, it builds and publishes one through `fork-build.yml`. Between upstream releases the owner can publish an interim release by running `fork-build.yml` manually on `master` with `release` checked. When the merge conflicts, tests fail, or the push is rejected (upstream changed workflow files, which `GITHUB_TOKEN` cannot push), the workflow leaves `master` untouched and opens an issue; the integration then falls back to the manual `upstream-sync/<baseline>` flow of ADR 0001.
